# Dev-C++ 环境配置指南

> 目标：装好编译器 + EasyX 图形库，能编译运行 `22届视觉仿真环境`。
> 全程约 10 分钟。

---

## 一、文件说明

| 文件 | 用途 |
|---|---|
| `Dev-Cpp.6.7.5.MinGW-w64.X86_64.GCC.10.3.Setup.exe` | **推荐安装**。小熊猫 Dev-C++（RedPanda），带代码补全和实时纠错，GCC 10.3.0 |
| `Dev-Cpp_5.11_TDM-GCC_4.9.2_Setup.exe` | 原生 Dev-C++ 5.11，TDM-GCC 4.9.2。二者用起来差不多，二选一即可 |
| `easyx4mingw_25.9.10.zip` | EasyX 图形库（MinGW 版），**两个版本都要装这个** |

---

## 二、安装步骤（Dev-C++ 6.7.5 / 小熊猫）

### 1. 安装 Dev-C++

双击 `Dev-Cpp.6.7.5.MinGW-w64.X86_64.GCC.10.3.Setup.exe`，一路下一步。
**记住安装路径**，下一步要用（下文以 `D:\TOOLS\Dev-Cpp` 为例）。

### 2. 安装 EasyX

解压 `easyx4mingw_25.9.10.zip`，把里面的文件拷进编译器目录：

| 压缩包里的文件 | 拷到 |
|---|---|
| `include\easyx.h`、`include\graphics.h` | `<安装路径>\MinGW64\x86_64-w64-mingw32\include\` |
| `lib64\libeasyx.a`、`lib64\libeasyxw.a` | `<安装路径>\MinGW64\x86_64-w64-mingw32\lib\` |

> 拷完最好把这两个 `.a` 再往 `<安装路径>\MinGW64\lib\` 也放一份。
> 多放几个位置不冲突，缺了反而可能链接不到。

### 3. 验证

打开 `22届视觉仿真环境\视觉仿真环境.dev`，按 **F11**（编译并运行）。
弹出仿真窗口即配置成功。

也可以直接双击 `22届视觉仿真环境\一键配置.bat`，它会自动检查编译器和 EasyX 是否就位。

## 三、如果你用的是原生 5.11

5.11 的 TDM-GCC 4.9.2 与新版头文件拷贝方式相同，但库文件不同：

| 压缩包里的文件 | 拷到 |
|---|---|
| `include\easyx.h`、`include\graphics.h` | `<安装路径>\MinGW64\x86_64-w64-mingw32\include\` |
| `lib32\libeasyx.a` | `<安装路径>\MinGW64\x86_64-w64-mingw32\lib\` |

其余步骤相同。**注意 5.11 的 GCC 4.9.2 较老，对 C11/C17 支持不全，若编译报错请换用 6.7.5。**

## 四、常见问题

| 现象 | 原因与解决 |
|---|---|
| 编译通过，链接时报 `undefined reference to initgraph` | EasyX 库没拷对位置；确认 `libeasyx.a` 在编译器的 lib 搜索路径里 |
| 找不到 `easyx.h` | 头文件没拷进 `include\`，或安装路径和上面写的不一致 |
| 链接时报 `EasyX is only for C++` | 你用 C 编译器编了 include 了 `easyx.h` 的文件（该头文件第 31 行有 `#error`）。EasyX 只能用于 C++；仿真工程已把 C/C++ 分开，直接用工程文件编译即可，不要单独编译 `code\*.c` |
| 项目打开后左边列表是空的 | `.dev` 文件被存成了 UTF-8；它必须保持 GBK 编码 + CRLF 换行 |
| VS 2022 那边报缺 EasyX | VS 装的是另一套 EasyX（官网 exe 安装包），与本文件夹的 MinGW 版互不通用 |

## 五、给 AI 的技术说明（疑难排查用）

> 本节供 AI 助手在排查配置类问题时参考，普通用户可忽略。

### 工具链与库的对应关系

- **6.7.5（RedPanda）= MinGW-w64 GCC 10.3.0，x86_64**。链接器是 GNU ld，只认
  GNU `ar` 格式的 `libeasyx.a`（zip 里 `lib64\` 下那份）；`EasyXa.lib` / `EasyXw.lib`
  是 COFF 格式，供 5.11 的 TDM-GCC 或 MSVC 使用。
- `-leasyx` 按 `libeasyx.a` 搜索。搜索路径可用
  `g++ -print-search-dirs` 确认；本工程 `.dev` 的 Linker 字段已含
  `-leasyx -lgdi32 -lole32 -static`。
- `easyx.h` 内部有 `#pragma comment(lib,"EasyXa.lib")`，GCC 不识别该 pragma
  （仅告警），因此 MinGW 下必须手工 `-leasyx`。
- `easyx.h` 第 31 行有 `#error EasyX is only for C++`：用 `gcc` 编译任何
  include 了它的文件都会直接报错。这就是「不能单独编译 `code\*.c`」的另一重
  保险 —— 不过 `code\*.c` 本来也不该 include 它（见 `readme.md` 约束）。

### 编译参数（工程内已配置，排查时对照）

- C 标准：`-std=c11`（MSVC 侧 `LanguageStandard_C=stdc11`）
- C++ 标准：`-std=c++17`（MSVC 侧 `stdcpp17`）
- 字符集：`-finput-charset=UTF-8 -fexec-charset=GBK`（MSVC 侧 `/utf-8`）
- 头文件路径：`-Ienv -Icode -I.`

**RedPanda 的坑**：`.dev` 的 `Includes=` 字段不会把 `-I` 传给编译器，
包含路径必须写在 `Compiler=`（C）与 `CppCompiler=`（C++）字段里。
当前 `.dev` 已正确配置；若用户报告「找不到头文件」先检查这两个字段。

### 工程结构约束（改动前必读）

- `code\*.c` 全部通过 `env\code_filelist.h` 进入 `env\simu_env.c`
  这一个编译单元（C11）。**它们自身绝不能再被单独编译**：
  - `.dev` 中 `Compile=0`、`Link=0`
  - `.vcxproj` 中 `ExcludedFromBuild=true`
  否则报 `redefinition of ...`。
- `env\code_filelist.h` 由 `tools\gen_filelist.ps1` 生成；
  该脚本同时同步 `.vcxproj` 与 `.dev` 的文件列表（`sync_vs_items.ps1` /
  `sync_dev_units.ps1`），均为「内容变化才写回」。
- `.dev` 文件格式：GBK 编码 + CRLF 换行 + `UnitCount` 必须等于
  `[UnitN]` 段数。任一不满足都会导致项目树空白或乱码。

### 运行期行为

- `env\disp_env.cpp` 的 `chdir_to_project_root()` 在启动时把工作目录
  切到「同时含 `code\` 与 `env\` 的那一级」，此后一律相对路径读 `pic\`。
  因此 exe 位置不影响图片加载；若用户报「渐变图」优先怀疑 `pic\` 缺失或
  `config.h` 的 `SCUT_PIC_DIR` / `SCUT_PIC_EXT` 配错，而不是工作目录。
- 字符转换分两条路，**不可混用**：
  - `to_tchar()`：界面文字，UTF-8 → wide（MSVC + Unicode）
  - `path_to_tchar()`：文件路径，`CP_ACP`（GBK）→ wide
    路径来自 `GetModuleFileNameA` 等 ANSI 接口，按 UTF-8 转会得到乱码路径，
    表现为 `loadimage` 失败、一直显示渐变图。
- 窗口尺寸在 `SCUT_Log` 内随日志行数自动增长，并重绘当前帧与历史日志
  （缓存于 `s_log_buf`）。改版面参数时注意同步 `disp_base_h()`。

### 自检工具

- `tools\verify_mixed.ps1`：验证 C/C++ 混合编译（8 项检查）。
  核心判据：`simu_env.o` 中 `image_process` 等符号**未修饰**（C 链接），
  且 gcc 拒绝 C++ 语法。
- `一键配置.bat`：纯 ASCII + CRLF；若用户改过它导致解析错乱，
  检查是否被存成 UTF-8 或 LF。
